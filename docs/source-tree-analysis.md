# NoteDri Mobile App - Source Tree Analysis

Annotated directory tree of the `notedri-app` repository. Every folder and most files are explained. (Last verified against the real filesystem on 2026-08-13; a previous revision was accurate as of ~2026-07-16 and had drifted - stale entries were removed and ~140 new/moved files were added below.)

---

## Top-Level Structure

```
notedri-app/
├── android/                   Native Android project shell
├── assets/                    Static image/icon assets for app store + runtime
├── docs/                      Project documentation (you are here)
├── modules/                   Local Expo native modules (config plugins + native code)
├── node_modules/              npm dependencies (not committed)
├── obd-fixtures/              Recorded OBD2/BLE session logs used for dev + tests
├── patches/                   patch-package diffs applied post-install
```

## `android/`

Native Android project generated by Expo. Contains `build.gradle`, `AndroidManifest.xml`, and Java/Kotlin wrappers. Required because `react-native-ble-plx` and the local `modules/` native modules are native code and cannot use Expo Go - a custom dev client is needed.

The `patches/` directory contains a `patch-package` diff that fixes a `build.gradle` issue in `react-native-ble-plx`. This patch is applied automatically via the `postinstall` script in `package.json`.

## `modules/`

Two local Expo native modules (built with the Expo Modules API, not third-party packages), each with an `android/` native project, a config-plugin entry, and a thin JS/TS bridge under `src/` with `.native`/`.web` split where a web/Expo-Go fallback is needed.

## `patches/`

Contains `patch-package` `.patch` files. Applied automatically by `npm run postinstall`. Current patches:

- `react-native-ble-plx+3.5.1.patch` - fixes a `build.gradle` compile issue on newer Android Gradle Plugin versions

If you add a new patch: `npx patch-package <package-name>`, then commit the resulting `.patch` file.

## `obd-fixtures/`

Recorded real-world OBD2/BLE session logs (JSON), used to replay sessions in dev and in the `src/services/obd/__tests__` suite instead of requiring a live adapter. Includes a `README.md` describing the fixture format and subfolders (`Notedri-Bluetooth/`, `obd-session-log/`) of raw capture logs.

---

## `__mocks__/`

Jest manual mocks (`expo-location.js`, `expo-task-manager.js`) that stub out native Expo modules the GPS trip tracker depends on, so `jest-expo` tests can run without a device.

---

## `_bmad/` and `_bmad-output/`

Installation and generated output of the BMAD agent framework (planning/spec/dev-loop skills such as `bmad-prd`, `bmad-architecture`, `bmad-dev-story`) used to drive parts of this project's own development process. `_bmad/` holds the framework's agent/workflow definitions (`bmm/`, `core/`, `custom/`, `scripts/`, `_config/`); `_bmad-output/` holds artifacts those skills produced (brainstorms, specs, deferred-work notes). Neither directory is part of the shipped app.

## `src/` - Application Source

### `src/agent/`

The "Nori" AI companion's tool-calling agent core - plain TypeScript, no React. See `docs/nori-agent-plan.md` for the design doc this folder implements section-by-section.

```
src/agent/
├── NoriAgent.ts             Top-level orchestrator wiring ConversationManager + ToolExecutor + ToolRegistry + SafetyPolicy
├── ConversationManager.ts   Turn loop: calls the LLM via api/nori.ts, or short-circuits through LocalIntentMatcher first
├── ToolRegistry.ts          Registers tool definitions and exports their schema in Anthropic tools[] shape
├── ToolExecutor.ts          Runs a requested tool call, prompting for user confirmation when a tool requires it
├── LocalIntentMatcher.ts    Deterministic on-device matcher for common questions - skips the LLM call entirely
├── LocalReplyTemplates.ts   Builds grounded Vietnamese replies straight from tool_result for matched local intents
├── KnowledgeClient.ts       Wraps the offline DTC dictionary as the knowledge.explainDTC tool
├── NoteDriApi.ts            Aggregates the app's existing api/* clients into the surface tools call into
├── VehicleContext.ts        Live vehicle snapshot source (obdLiveMonitor + BleService + ObdReader) implementing IVehicleIO
├── progressText.ts          Vietnamese "thinking..." progress copy per ProgressStage, for chat/voice popover UX
├── useInitNoriAgent.ts      Hook that constructs/tears down the NoriAgent instance and wires it into noriAgentStore
├── types.ts                 Core agent types: conversation turns, tool calls/results, schema types
├── safety/SafetyPolicy.ts   Single gatekeeper deciding which tools may run while the vehicle is moving
├── platform/types.ts        IVehicleIO/PlatformAdapter contract - phone today, other head units later
├── platform/MockVehicleAdapter.ts  Fake adapter for tests/dev without a real BLE connection
├── platform/TestHarness.ts  Drives NoriAgent end-to-end against MockVehicleAdapter for automated tests
├── tools/vehicleTools.ts    Read-only vehicle.getSpeed/getRPM/... tools sourced from VehicleContext
├── tools/knowledgeTools.ts  knowledge.explainDTC tool
├── tools/businessTools.ts   Read-only tools over app data: trip history, driving-score comparisons, etc.
├── tools/writeTools.ts      Mutating tools (authority='mutating'), e.g. logging a reminder/refuel via chat
└── __tests__/               NoriAgent/TestHarness/progressText unit tests
```
