- (technique) started First Principles Thinking

- (idea by coach) Enforce grounding structurally: LLM output shape is restricted to (a) a tool_call or (b) natural-language wrapping of a completed tool result, via function-calling schema - not just a prompt instruction
- (idea by coach) ConversationManager should store tool-call transcripts as the source of truth; free-text chat history is a rendering side effect, never the canonical record
- (idea by coach) Model NoriAgent's core loop as an explicit state machine (Listening -> Understanding -> Executing -> Responding) mirrored directly in code structure, not a generic chat loop
- (idea by coach) Every VehicleCache/tool value has an age - bake a timestamp/staleness flag into every tool response so Nori can say things like 'dang chay 68km/h (2 giay truoc)'
- (idea by coach) Voice input is lossy (STT errors) - add an explicit confidence/fallback layer before Intent Detection instead of assuming clean transcribed text
- (idea by coach) Business logic already lives in the Laravel backend for fuel/maintenance - ToolRegistry entries for those should be thin HTTP wrappers with zero duplicated validation logic client-side
- (idea by coach) Question whether Intent Detection and Tool Selection need to be separate stages at all, or whether a single LLM function-calling step can collapse both and simplify the architecture
- (idea by coach) Write an explicit architectural invariant doc defining 'Agent' for this codebase as a bounded executor of registered capabilities with context memory, never a generator of open text
- (idea by coach) Rename the deeper principle behind 'Agent not chatbot': a Tool-grounded response contract enforced by schema, with every output required to cite a tool_result_id

- (idea by coach) Real constraint: noisy cabin hurts STT accuracy - require a light confirmation step (voice + quick visual/haptic) before executing destructive tools, never on STT alone
- (idea by coach) Real constraint: driver distraction/safety law - define a formal DrivingSafetyPolicy that gates which tools are even offered while speed > 0 (e.g. block ocr.scanReceipt while driving)
- (idea by coach) Drop the imagined constraint 'wake word must ship in v1' - reclassify it as a later milestone, freeing v1 scope to focus on Tool Registry correctness

- (idea by coach) Real constraint: per-voice-turn LLM API cost at scale - short-circuit repeated identical queries within a session at the ToolRegistry layer, and consider a smaller/cheaper model just for JSON-to-natural-language formatting

- (technique) started TRIZ Contradiction

- (idea by coach) Contradiction: instant responsiveness while driving vs accuracy needing a round-trip - resolve with a two-phase response: an instant local filler acknowledgment, then the real answer once the tool resolves
- (idea by coach) Contradiction: one reusable generic core across platforms vs platform-specific richness - resolve with platform-agnostic tool JSON plus an optional hints object each adapter honors only as much as it can render
- (idea by coach) Contradiction: centralized Tool Registry control vs decentralized third-party extensibility - resolve with a two-tier registry: reviewed core tools plus sandboxed, reduced-permission extension tools
- (idea by coach) Contradiction: continuous vehicle awareness vs privacy/battery expectations - resolve with the invariant that VehicleCache is local-only by default and nothing leaves the device unless a tool call is explicitly triggered

- (insight by coach) SYNTHESIS: (1) Grounding must become a structural/schema-enforced contract (grounding validator + tool_result_id citation), not a prompt instruction - this is the concrete payoff of the Agent-not-chatbot framing. (2) The real near-term risk is plumbing not the LLM: OBDManager/VehicleCache belong in a native foreground-service layer decoupled from the RN JS thread, independently reached via Constraint Mapping, Chaos Engineering, Nature's Solutions and Time Horizon. (4) Mutating/destructive tools need one shared Tool Execution Policy layer (confirmation, locking, offline queue, safety gating) instead of per-tool logic.
